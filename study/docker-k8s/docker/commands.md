# Docker Commands

This document covers common Docker commands used for building, running, managing, debugging, and publishing containers.

---

# 1. Building Images

## docker build

### What it does

Builds a Docker image from a Dockerfile.

Docker reads the Dockerfile, executes build instructions (`RUN`, `COPY`, etc.), and creates an immutable image that can later be used to create containers.

### Syntax

```bash
docker build [OPTIONS] PATH
```

### Example

```bash
docker build -t my-app .
```

### Explanation

- `-t` assigns a name/tag to the image.
- `.` tells Docker to use the current directory as the build context.

### Common options

Build without cache:

```bash
docker build --no-cache -t my-app .
```

Useful when:
- Debugging Dockerfile issues.
- Dependencies changed but Docker is using old cached layers.

Use a different Dockerfile:

```bash
docker build -f Dockerfile.dev -t my-app .
```

Useful when:
- Having separate development and production Dockerfiles.

# 2. Running Containers

## docker run

### What it does

Creates and starts a container from an image.

If the image does not exist locally, Docker attempts to download it from a registry.

### Syntax

```bash
docker run [OPTIONS] IMAGE
```

### Example

```bash
docker run my-app
```

---

## Run in background

```bash
docker run -d my-app
```

`-d` runs the container in detached mode.

The container continues running in the background.

---

## Map ports

```bash
docker run -p 8080:80 nginx
```

Maps a host port to a container port:

```
host:container

8080 -> 80
```

Example:

```
localhost:8080
        |
        v
container port 80
```

---

## Give container a name

```bash
docker run --name web nginx
```

Without this, Docker generates a random container name.

---

## Automatically remove container

```bash
docker run --rm my-app
```

Deletes the container automatically after it exits.

Useful for:

- Testing
- Short-lived programs
- CLI tools

Without `--rm`, stopped containers remain and can be viewed with:

```bash
docker ps -a
```

---

## Pass environment variables

```bash
docker run -e DATABASE_URL=mydb app
```

Passes configuration values into the container.

Commonly used for:

- Database URLs
- API keys
- Application configuration

# 3. Managing Containers

## docker ps

### What it does

Lists currently running containers.

```bash
docker ps
```

Show all containers, including stopped ones:

```bash
docker ps -a
```

Useful for:

- Finding container IDs
- Checking container status
- Finding container names

---

## docker stop

### What it does

Stops a running container gracefully.

Docker sends a termination signal first, allowing applications to clean up before shutting down.

### Example

```bash
docker stop my-container
```

---

## docker start

### What it does

Starts an existing stopped container.

### Example

```bash
docker start my-container
```

Useful when:

- You stopped a container but want to reuse it.
- You don't want to create a new container.

---

## docker restart

### What it does

Stops and starts a container.

### Example

```bash
docker restart my-container
```

Useful when:

- Application is stuck.
- Configuration changed.

---

## docker rm

### What it does

Removes a stopped container.

### Example

```bash
docker rm my-container
```

Force remove a running container:

```bash
docker rm -f my-container
```

Useful for:

- Cleaning old containers.
- Removing containers before recreating them.

---

# 4. Inspecting Containers

## docker logs

### What it does

Displays output generated by the application running inside the container.

### Example

```bash
docker logs my-container
```

Follow logs live:

```bash
docker logs -f my-container
```

Useful for:

- Debugging crashes.
- Checking startup errors.
- Monitoring application output.

---

## docker exec

### What it does

Runs a command inside an already running container.

### Example

```bash
docker exec -it my-container bash
```

Options:

- `-i` keeps input open.
- `-t` creates an interactive terminal.

Useful for:

- Inspecting files.
- Checking environment variables.
- Debugging applications.

---

## docker inspect

### What it does

Displays detailed information about Docker objects.

### Example

```bash
docker inspect my-container
```

Shows:

- Container configuration
- Network information
- Volumes
- Environment variables

---

## docker stats

### What it does

Displays live resource usage.

### Example

```bash
docker stats
```

Shows:

- CPU usage
- Memory usage
- Network usage

Useful for finding performance issues.

---

## docker cp

### What it does

Copies files between the host and a container.

### Copy from container:

```bash
docker cp my-container:/app/log.txt .
```

### Copy into container:

```bash
docker cp config.json my-container:/app/
```

Useful for:

- Extracting logs.
- Debugging.
- Moving files temporarily.

---

# 5. Managing Images

## docker images

### What it does

Lists locally available images.

### Example

```bash
docker images
```

Shows:

- Repository name
- Tag
- Image ID
- Size

---

## docker rmi

### What it does

Removes an image.

### Example

```bash
docker rmi my-app
```

Force removal:

```bash
docker rmi -f my-app
```

Useful for:

- Cleaning old images.
- Removing unused builds.

---

## docker pull

### What it does

Downloads an image from a registry.

### Example

```bash
docker pull nginx
```

Useful when:

- Getting images from Docker Hub.
- Updating to a newer image version.

---

## docker tag

### What it does

Creates another name/tag for an image.

### Example

```bash
docker tag my-app myrepo/my-app:v1
```

Commonly used before pushing images to a registry.

---

# 6. Registry Commands

## docker login

### What it does

Authenticates with a container registry.

### Example

```bash
docker login
```

Required before pushing private images.

---

## docker push

### What it does

Uploads an image to a registry.

### Example

```bash
docker push myrepo/my-app:v1
```

Used for:

- Sharing images with teammates.
- Deploying images to servers.
- CI/CD pipelines.

---

# 7. Cleanup

## docker system prune

### What it does

Removes unused Docker resources.

### Example

```bash
docker system prune
```

Removes:

- Stopped containers
- Unused networks
- Dangling images

---

Remove all unused images:

```bash
docker system prune -a
```

Warning:

This removes cached images and may require rebuilding them later.

---

# Common Workflow

Build an image:

```bash
docker build -t my-app .
```

Run a container:

```bash
docker run --rm my-app
```

Check running containers:

```bash
docker ps
```

View logs:

```bash
docker logs container-name
```

Enter a running container:

```bash
docker exec -it container-name bash
```

Stop a container:

```bash
docker stop container-name
```

Remove old containers:

```bash
docker rm container-name
```

Clean unused resources:

```bash
docker system prune
```
